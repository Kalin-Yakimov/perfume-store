# Browser тестове на потребителските потоци

Тестовете използват истинския Next.js storefront, Medusa HTTP приложение и PostgreSQL. Няма подменени успешни отговори от приложението. Отделен сценарий умишлено прекъсва браузърната заявка за търсене, проверява съобщението за грешка и възстановява истинската заявка за повторния опит. Playwright стартира отделен Chromium, не личния Chrome профил.

## Покритие

- Каталог: изчерпаните продукти остават последни, без цена и без възможност за покупка; количеството е 0.
- Търсачка: обем/цена за наличните продукти и обозначение за изчерпаните; отказ на връзката не се представя като празен резултат, а повторният опит зарежда истинските продукти.
- Любими за гост: добавяне, запазване след презареждане, премахване.
- Отливки: избор на 10 мл, избраният контур, правилен вариант и цена в кошницата.
- Кошница: увеличаване/намаляване, запазване на количеството и премахване след презареждане.
- Невалиден вход и директно отваряне на защитените страници без профил.
- Регистрация → истински SMTP имейл → потвърждение → автоматичен вход в оригиналния браузър. Повторното използване на линка се отхвърля.
- Потвърждение от друг браузър не го вписва автоматично; след потвърждение обичайният вход работи.
- Профил: редакция на име; адреси: добавяне, редакция, изтриване и проверка след презареждане.
- Забравена парола: получаване на SMTP линк, нова парола, отказ с предишната парола и успешен вход с новата.
- Гост и вписан клиент: доставка → тестово ръчно плащане → лични данни → поръчка → потвърждение → празна кошница. При регистрация съществуващата гост кошница се запазва; клиентската поръчка се вижда в историята.
- Мобилен viewport: каталог → любими → продукт → кошница без хоризонтално излизане от екрана.

След браузърните сценарии backend тестът проверява и двете създадени поръчки в базата: артикули, получател в България и правилна доставка.

Локална проверка на 04.10.2026: **13/13 браузърни сценария**, без retries, и backend проверката на поръчките минават успешно. Тестовете са пуснати срещу отделния cluster на порт 55439. Това не удостоверява бъдещия GitHub Actions run или реалните платежни/куриерски услуги.

Също минават всички 315 unit теста, lint, typecheck и пълният forced production build. При build без нормално работещ backend sitemap-ът използва съществуващия резервен списък; това е очаквано предупреждение, не провален build.

## Безопасност и стартиране

Не използвайте базата на магазина. Нужен е отделен локален PostgreSQL cluster/container с потребител, който може да създава тестови бази. Runner-ът отказва външни хостове, липсващ порт, порт 5433 на локалния проект и база, различна от началната `/postgres`. Medusa създава случайно именована тестова база и я премахва при обичайното приключване. Прекъсване на процеса със сила може да остави само временни тестови данни в този отделен cluster.

След `npm ci`, инсталирайте тестовия браузър веднъж:

```powershell
npm exec --workspace=@dtc/storefront -- playwright install chromium
```

Пример за отделен test cluster на порт 55439 (заменете с вашите тестови credentials, не с тези на магазина):

```powershell
$env:E2E_DATABASE_URL = "postgres://test_user:test_password@localhost:55439/postgres"
npm run test:e2e
Remove-Item Env:E2E_DATABASE_URL
```

Не е нужно да пускате нормалния сайт. Runner-ът стартира собствен backend, SMTP inbox и Next.js на свободни локални портове. Копира само кода, public assets и необходимите конфигурации в генерирана `.e2e-app/run-*` папка; **не копира `.env` файлове**, не променя нормалните Next.js type declarations и build output. Спира само създадените от него процеси и премахва собственото временно копие.

SMTP настройките се подават само на тестовия процес. Пощата е локална, без препращане; приема само синтетични адреси `@example.invalid`. Данните за получените линкове са в паметта и се четат през защитен с временен ключ локален endpoint. Реалната АБВ поща не се използва. Браузърните заявки към външни домейни са блокирани.

## Автоматични проверки и ограничения

GitHub Actions има отделен `customer-flows` job със собствен PostgreSQL 17 service, локална поща и Chromium. На Linux инсталацията използва `playwright install --with-deps chromium` съгласно [официалното CI ръководство](https://playwright.dev/docs/ci). Job-ът не изисква реални SMTP или платежни secrets. При отказ качва screenshot/trace/report за 7 дни. Въпреки синтетичните данни тези файлове могат да съдържат тестови пароли/еднократни линкове: не ги публикувайте и не ги commit-вайте.

Сценариите засега работят с Next.js development server; production build и реалният production cache се проверяват отделно от съществуващите quality/cache jobs. Мобилната проверка е Chromium viewport, не реален iPhone/Safari. Реални карти, Apple Pay, Google Pay, Revolut и куриерски карти/товарителници не са включени и не се активират от тези тестове. Performance/load testing и пълна accessibility проверка също са отделни задачи.

## Открита поправка

Директно отваряне на подстраница на профила от гост показваше 404 и правеше ненужни неоторизирани заявки за поръчки. Добавен е fallback за login parallel slot и проверки на клиентската сесия преди dashboard данните. Така невписаният посетител вижда вход, без достъп до частните данни. Браузърният сценарий проверява поръчки, профил, адреси и детайли на поръчка.

Workspace обхватът е ограничен до `apps/*`, а Jest игнорира временното `.e2e-app` копие. Така паралелна локална build/unit проверка не го третира като дублирано приложение или пакет.
