# Локална бързина на storefront — 5 октомври 2026

## Причини и промени

`start-dev.cmd` използва `next dev --turbopack`: страниците се компилират при първо посещение, а публичните заявки са без постоянен Next.js кеш за незабавно виждане на админ промени. Това не е представително за оптимизирания build. При проверката първото отваряне след промяна на конфигурацията отне до 8,6 секунди; повторните отваряния бяха значително по-бързи.

- Българските публични адреси вече не чакат заявка за региони в middleware. Реалният регион/цените продължават да се валидират при зареждане на данните. Други държави запазват API проверката.
- Навигацията и съдържанието се изпращат, без да чакат профила, кошницата, езиците и доставките. Тези части имат отделни Suspense граници.
- Еднаквите четения на кошницата се споделят само в рамките на един server render чрез React `cache`. Мутациите четат прясно; лични данни не се записват в общ постоянен кеш.
- SDK в браузъра чете достъпната locale cookie директно, вместо да прави допълнителен server-action round trip за всяка заявка. Auth cookies остават httpOnly.
- Автоматичният избор на първата разфасовка вече не прави второ отваряне на продукта чрез `router.replace`. Изричният избор, споделените variant URL и връщането в историята остават поддържани.
- Търсенето използва директния публичен адрес без допълнително `/bg` пренасочване и пропуска taxonomy заявката, когато няма такава информация за обогатяване.
- Каталогът не изчислява ненужни складови количества за unmanaged variants; при проекцията пропуска и backorder variants. Данните за текущата страница и facet филтрите се зареждат паралелно. Наличностите/резервациите не са променяни.
- `optimizePackageImports` е включен за Medusa иконите.

## Локален preview

След спиране на development сървърите: `D:\New_project\start-preview.cmd`, или `npm run preview` от monorepo при вече работещ PostgreSQL. Скриптът стартира локалния backend в development режим, изчаква health проверката, компилира frontend в отделна `.next-preview` папка и го стартира на `http://localhost:8000`. Двата процеса споделят временен ключ за подписаното обновяване на кеша. Не се записват ключове в `.env`.

Това не е deployment. Плащанията/куриерите остават тестови. За промяна на кода с автоматично презареждане използвайте `start-dev.cmd`; preview изисква рестарт и повторно компилиране. Стартерът отказва да замести процеси на заети портове и спира само собствените си процеси. Използвайте `localhost`, който съвпада с hostname на Next.js и CORS настройките на backend.

## Измерване

Последователни HTTP GET заявки без клиентски токен или кошница към локалния сайт; измерен е целият HTML отговор, не изтеглянето на изображения, browser hydration или Core Web Vitals. Backend е един и същ локален development сървър. Сравнението е между режимите след промените, а не доказателство за ускорение само от кодовите промени.

| Страница | Повторно отваряне, development | Повторно отваряне, компилиран frontend |
| --- | --- | --- |
| Парфюми | 0,50 s | 0,13–0,16 s |
| Отливки | 0,44 s | 0,13–0,16 s |
| Дизайнерски къщи | 0,37 s | 0,05 s |
| Парфюмни нотки | 0,38 s | 0,05 s |
| Вход | 0,39 s | 0,03–0,04 s |
| Празна кошница | 0,43 s | 0,04–0,05 s |
| Продукт, цяла бутилка | 0,92 s | 0,12–0,13 s |

Компилираният frontend беше проверен временно на отделен порт 8100, без спиране на текущия development сайт. Browser search към backend от 8100 е извън разрешения CORS origin; нормалният preview стартер използва 8000. Търсенето е проверено в браузъра на 8000, а продуктите/разфасовките — и на компилираната версия.

## Проверки и ограничения

367 unit теста минават (15 за стартерите, 158 backend, 194 storefront), плюс lint, TypeScript и пълен build на двете приложения. Новите тестове покриват стриймването при бавни заявки, изолацията на render четенията, прясното четене при промени на кошницата, variant URL логиката, middleware, locale headers и preview безопасността. Пълният build откри и поправени по-стари Next.js 15 route несъвместимости: непозволен export в collection page и непредвидени Promise params в order transfer страниците.

Не са променяни тарифите, платежните интеграции, базата или Redis конфигурацията. Не е правено пълно повторно изпълнение на browser E2E suite с поръчки/регистрация в тази проверка. Локалните guest измервания не заменят профилиране с много продукти, активна кошница и вписани клиенти.
